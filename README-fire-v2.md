# تحديث 4.6.0 — الحريق والشحن (MAS)

## خطوات التركيب
1. **Supabase → SQL Editor → New query**: الصق محتوى `setup_fire_v2.sql` واضغط Run (مرة واحدة، آمن لو اتشغّل تاني).
   - هو بيطبع في تبويب Messages التعريف القديم لقيد `profiles_section_check` قبل استبداله.
2. ارفع كل ملفات المجلد على GitHub (استبدال الملفات القديمة).
3. افتح **الحريق ← الأفران** وحدّد **نوع كل فرن** (بسكوت/جليز). الأفران اللي ليها عمليات قديمة من نوع واحد اتحدد نوعها تلقائي في الـ Migration؛ الباقي لازم تحدده بإيدك، وإلا مش هتظهر في اختيارات الحريق والشحن.
4. من **المستخدمين** حدد تخصص كل عامل في الحريق.

## تخصصات العمال (profiles.fire_role)
| التخصص | يعمل | لا يعمل |
|---|---|---|
| متخصص أفران البسكوت | يبدأ/يسجّل/يطفّي حريق **البسكوت** + يصوّر العداد، يعدّل سجلاته هو في نفس اليوم | شحن، حريق الجليز، حذف، سجلات غيره |
| متخصص أفران الجليز | نفس الشيء لحريق **الجليز** | شحن، حريق البسكوت، حذف |
| مسؤول شحن البسكوت | يسجّل شحن **البسكوت** ويعدّل شحناته في نفس اليوم | حريق، شحن الجليز، حذف |
| مسؤول شحن الجليز | يسجّل شحن **الجليز** ويعدّل شحناته في نفس اليوم | حريق، شحن البسكوت، حذف |
| مشرف قسم الحريق والشحن | كل شيء في الحريق والشحن: إنشاء/تعديل/حذف في أي وقت، إدارة الأفران، سجل المراجعة | أي شيء خارج قسم الحريق |

- التخصص بيتعيّن للأدوار «مسجّل إنتاج» و«مسؤول قسم» اللي قسمهم الحريق. المدير بس هو اللي يغيّر التخصص (السيرفر بيمنع غيره).
- **حساب في قسم الحريق بدون تخصص** (الحسابات القديمة) بيفضل بصلاحيته القديمة (يسجّل كل شيء) لحد ما تحدد له تخصص — عشان ما نكسرش حسابات شغّالة. مسؤول القسم (manager) والمدير = مشرف تلقائيًا.
- صاحب المصنع: عرض فقط (كما هو).
- الصلاحيات بتتفرض **على مستوى قاعدة البيانات** (Triggers + الدوال)، مش الواجهة بس.

## التغييرات
- الحريق مستقل: `firing_operations.load_id` بقى اختياري (للتتبع)، وللعملية أصنافها وعربيتها وملاحظتها (`firing_operation_items`, `cart_code`, `note`).
- الشحن مستقل: بيتسجّل معتمد مباشرة، من غير حريق.
- أنواع الأفران: `firing_kilns.kind`، وTrigger بيمنع ربط شحنة/حريق بفرن من نوع مختلف أو بشحنة من نوع مختلف.
- دوال جديدة: `firing_ship_save/ship_delete`, `firing_fire_save/fire_delete`. الدوال القديمة لسه موجودة (توافق مع النسخ المخزّنة)، لكن بتخضع لنفس Triggers.
- حذف شحنة مرتبطة بحريق: العملية بتفضل، وبتاخد أصناف الشحنة ورقم العربية قبل فك الربط. حذف عملية: الشحنة مش بتتأثر.
- سجل المراجعة `firing_audit` (من/متى/قبل/بعد) — صفحة «المراجعة» + «سجل التعديلات» على كل سجل.
- الواجهة: لوحة تحكم، تبويبات (حريق بسكوت/جليز، شحن بسكوت/جليز، الأفران، جارية، مكتملة، السجل، التقارير والطباعة، المراجعة)، اختيار تاريخ/وقت موحّد، تقارير A4.

## الرجوع لو حصلت مشكلة
الـ Migration إضافي (أعمدة وجداول جديدة، `load_id` بقى nullable). مفيش حذف بيانات. الرجوع للنسخة القديمة من الملفات شغّال، لكن عمليات حريق بدون شحنة مش هتظهر صح فيها.

## 4.6.1 — استرجاع البيانات القديمة
1. شغّل `setup_fire_restore.sql` في Supabase → SQL Editor → Run (بعد setup_fire_v2.sql).
2. ارفع `fire.html` و`config.js` و`sw.js`.
3. من **الحريق ← المراجعة**: كل عملية «حذف» عليها زر **استرجاع السجل المحذوف**، وآخر «تعديل» على كل سجل عليه زر **رجوع للقيم القديمة**. (للمدير ومشرف الحريق فقط.)
- صور العداد المحذوفة مش بترجع (ملفاتها اتمسحت من التخزين).
- لو شحنة اتحذفت وعمليتها فضلت مستقلة، الاسترجاع بيرجّع الشحنة بس (من غير إعادة الربط).
- **حذف البيانات القديمة (المدير فقط):** من **المراجعة** ← «حذف البيانات القديمة»: اختار تاريخ (قبل النهارده بأسبوع على الأقل)، هتشوف عدد الشحنات والعمليات قبل التأكيد. العمليات الجارية مش بتتحذف، وكل سجل بيتسجّل في المراجعة (فتقدر تسترجعه، إلا صور العداد). دالة `firing_purge_old` في نفس ملف `setup_fire_restore.sql` (اتشغّله تاني).
